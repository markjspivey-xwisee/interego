INTEREGO HEALTH CONNECTIONS

How this bridge handles your data

Personal source connections, operated by the owner of this Interego deployment. Updated October 31, 2026.

What is imported

The bridge requests the medical-record, wearable or selected iPhone readings you authorize. Each source needs its own permission. It preserves source labels, clinical dates and retrieval dates. Source availability does not establish complete medical-record coverage.

Oura connection status

Retained Oura imports and Interego agent access are disabled. An Oura account and OAuth approval alone do not authorize this use. Additional provider authorization and a compliant connection design are required before retained imports can be enabled. No alternative Oura MCP connection is implemented in this bridge.

Where records and credentials go

Imported records and source refresh tokens are encrypted in the deployment's dedicated storage. The deployment operator controls the encryption key. This is server-managed encryption, not a claim of end-to-end encryption against the operator. Authorized Interego agents acting for the same account can request private records through verified signed actions.

Short-lived Interego browser credentials are discarded after the sign-in proof is verified. The browser keeps an expiring session cookie. The iPhone pairing credential only permits uploads of the selected metrics; it cannot read the stored record. Source credentials and record contents are not intentionally logged.

Who can access imported records

The deployment operator and hosting providers operate the server infrastructure. An authorized Interego agent acting for the record owner's account can retrieve the full imported source record, including raw clinical content. Approval applies generally to that account's authorized agents; the bridge checks the owner on each signed request and does not provide a separate permission screen for each agent or record. It does not send a new notification or ask for approval each time a record is read.

The signed record interface provides the stored clinical records, subject to its pagination and request limits. This means the records actually imported, rather than a guarantee of the complete source medical chart. This version does not provide a user-facing report of who has accessed each record.

Sharing and public publication

This bridge does not automatically publish source records, ring scores, device samples or medical notes to the public Health Atlas. Authorizing a source connection is not authorization for a new public release. If you ask an agent to use private records in another service, that separate request determines the sharing.

Disconnecting and retention

Pausing private imports stops new intake. Disconnecting removes the bridge's stored source credentials or revokes iPhone upload permissions locally. You can also revoke the app in the source provider's account. Imported records are retained indefinitely until the deployment operator removes them. There is no automatic record expiry or cleanup when an Interego account is closed. Existing records remain available to the owner's authorized agents after imports are paused or a source is disconnected. Removal currently requires deployment-operator action; this first version does not provide a self-service record-deletion screen.

Limits

There is no continuous polling by default. Apple Health requires the device's permission and can be unavailable while the phone is locked. Oura and Apple Health may contain overlapping readings; the bridge preserves provenance and does not add mirrored observations together. This is a personal health-record integration, not a provider's electronic health record or a clinical decision system.
