I2IDL-X

An agentic superset of the I2IDL Digital Learning Glossary. It gives all @@I2IDLX_SLOT_4@@ concepts agentic kinds, interpretant layers, hypermedia controls and governed crosswalks to Foxxi and Interego, and makes the glossary a semantic layer for the industry's data: what each concept classifies, aligned with BFO 2020, gist, DOLCE-UltraLite, gUFO, PROV-O, schema.org and the learning-industry vocabularies. Nothing in the glossary is copied or changed. The graphs are published as linked data on Interego; this page is their reference.

Use it as an agent

An agent needs only the catalog IRI. Everything else is discovered from it.

  1. Read the catalog.

    GET the catalog IRI as Turtle, or with ?format=markdown to see its controls as readable blocks. It states the SPARQL service's limits before you spend a call.

  2. Pick a control by its action IRI.

    Read ports name the capability they need. Write ports also name the shape the relay checks before anything is stored, and write only to your own pod.

  3. Act through Interego.

    Pass the catalog IRI as the descriptor. It stays the same when the catalog is republished, and the follower re-resolves each target from the published graph. For SPARQL, send the query text itself as a string payload to the POST port:

    act @@I2IDLX_SLOT_32@@

    Reads without input take an empty payload:

    invoke_affordance @@I2IDLX_SLOT_33@@
  4. Follow an enactment to the capability.

    The enactments graph links a concept to action IRIs through i2x:realizedBy, i2x:measuredBy and the other roles. Each action IRI redirects to the manifest that defines it; pass that manifest as the descriptor:

    invoke_affordance @@I2IDLX_SLOT_34@@
  5. Or call the services directly.

    Plain HTTP works too. The SPARQL GET port takes ?query=; the POST port takes the query as the body.

Semantic layer

An I2IDL concept is a term. The things it classifies (an LRS deployment, a quiz session, a teacher, a badge) are typed in upper ontologies and peer vocabularies from one link, i2x:isClassifiedBy. Each of the @@I2IDLX_SLOT_37@@ concepts has one of @@I2IDLX_SLOT_38@@ referent categories: @@I2IDLX_SLOT_39@@ follow I2IDL's own type, @@I2IDLX_SLOT_40@@ are decided by the definition, each with its reason (@@I2IDLX_SLOT_41@@). Each category is aligned once, with a rationale, in @@I2IDLX_SLOT_42@@, together with I2IDL's own record types and the Interego and Foxxi vocabularies. All of it is proposed (Hypothetical): a reasoner using it reaches Hypothetical conclusions.

Using it

  1. Follow three ports.

    port-vocabulary, port-alignments and port-referents carry the whole layer.

  2. Classify without a reasoner.

    Load what they return with your own data and run q-classify, plain SPARQL 1.1: it reaches what OWL 2 RL reaches for your data's types.

  3. Or reason in full.

    Add the upper ontologies' own files and run an OWL 2 RL engine or a DL reasoner to find contradictions such as a quiz that is also a teacher.

  4. Publish your context graph.

    port-publish-classified writes your resources, classified by I2IDL concepts, to your own pod; the relay checks them against the shapes first.
