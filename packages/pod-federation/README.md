# Opt-in pod federation adapter

This Layer 3 package composes existing Interego recipient encryption with an invitation and signed HTTP transport. Local and hosted applications use the same service; it does not change the protocol or open a raw Solid storage endpoint.

Every new service is disabled. A host supplies protected durable storage, the current pod binding, an owner-controlled permanent endpoint and authenticated owner controls. `handle(Request)` serves only the public peer routes beneath that endpoint. Enabling the service is separate from exposing a listener or tunnel. The host pauses it when the pod or public transport stops.

An invitation is valid for fifteen minutes and can create one pending request. Both owners compare its displayed verification code; the inviting owner approves the requesting key. Peers use separate persisted Ed25519 `did:key` signing and X25519 encryption keys. These are not the pod's master content key, an existing hosted login identity, or proof that a chosen display name identifies a person. Hosted applications bind management to their existing authenticated owner; local applications use native owner controls.

Owners choose exact resources to send. The adapter preserves canonical IRIs, media types and the exact representation inside a recipient-encrypted envelope from `@interego/core`. It sends selected snapshots only. It does not add editing, automatic synchronization, offline queues, notifications or access to future resources. Disconnect blocks future transfers in both directions at this instance; it does not retract copies already received, and an offline peer may continue to display an old connection. Received snapshots remain locally readable while sharing is paused.

Signed peer messages bind the issuer, exact recipient endpoint, action, fresh timestamp, nonce and payload. State is committed before a successful authorization or delivery response. Replay records persist across service restarts. Invitations expire after fifteen minutes; peer requests expire after five minutes. Caps are eight open invitations/requests, thirty-two peers, sixteen resources per send, sixty-four received snapshots and sixty-four sent history rows, with a maximum representation of 128 KiB including its JSON wrapper. Owners can remove individual received copies and clear sent display history, including while paused. These local retention controls preserve peer authority and replay protection and never delete a remote copy. Resetting sharing clears this adapter's identity, peer authority and retained snapshots; it does not delete the pod's source notes.

The production transport checks all DNS answers, rejects private/reserved addresses, pins the chosen public IP into the HTTPS socket and refuses redirects. Request and response sizes, concurrency and time are bounded. A trusted host may inject a transport for tests; production hosts should retain the default transport. The explicit loopback option exists for isolated native verification only.

`ProtectedFederationStore` uses a host-supplied protector (Windows DPAPI in the desktop application), atomic bounded writes and strict regular-file checks. Hosted applications inject their own encrypted conditional store. This package never starts a listener or provisions an account, domain or tunnel.

Hosted compositions set `refreshState: true` to reload peer authority before each operation and require conditional writes. An outbound authorization intent is committed before any snapshot request is sent; a compare-and-swap failure pauses the instance. Active transport state is process-local. Multi-replica hosting requires affinity until a coordinated lease/transport lifecycle is supplied, and revocation cannot retract an already authorized in-flight delivery.
