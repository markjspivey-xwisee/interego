# Prose procedure reference — unmeasured

This is the same evidence-review task expressed as ordinary instructions for an LLM or agent to interpret. It is not an executed comparison condition and has no measured latency, model usage, or cost.

Given the application pod, catalog graph IRI, expected state identifier, and course HyperMarkdown link, discover the current catalog head. Require an unambiguous current head, verified and bound authorship, verified artifacts, and a complete verified release history. Do not report success if any required evidence is absent or inconsistent.

Inspect the catalog's live controls. Select its unique executable, input-free Refresh and verify GET control and follow the exact advertised action and descriptor authority through the available authenticated connection. Recheck the returned trust and history. If the observed release state differs from the caller's expectation, return the observed state for a decision. After a decision, start a new discovery run with explicit inputs.

Follow the accepted readiness record and FOXXI result links. Verify their signatures/content bindings and decoded document digests, and check that their candidate, suite, readiness, and grade totals agree. Follow the readiness record's portable performance-record link. Keep historical assessment evidence distinct from a new performance or learning event.

Read the supplied course HyperMarkdown and follow its typed JSON catalog link. Match the course identifier across the live catalog, HyperMarkdown, and accepted results, and match its assessment count to the recorded total. Include the advertised SCORM manifest and package links. Do not describe the package as executed or conformant merely because those links exist.

Re-read the current application-state and catalog heads before reporting. If either changed, stop rather than reporting the stale observation. Return the verified release status, performance totals, course links, and the historical xAPI reference with its source limitation. Do not claim a fresh LRS statement read unless one actually succeeded.

If authorized to record the completed review as a new performance event, discover the current FOXXI recording control and its authority, supply the observed success and measured duration, sign as required, and follow that advertised control. Keep this write's receipt and timing separate from the read-only review. A receipt is not proof of new competence.

A future comparison must state the agent/model, prompts, script policy, cold or warm state, access, metering, and stopping rules before collecting trials. This reference does not prohibit ordinary code or reuse.
