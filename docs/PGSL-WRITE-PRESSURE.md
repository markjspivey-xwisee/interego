# PostgreSQL physical write admission

Set `PGSL_PG_MAX_DATABASE_BYTES=48000000000` on every CSS/PGSL PostgreSQL writer connected to the replacement 64 GB database. The limit is opt-in; unset preserves the existing adapter behavior. No Railway control-plane credential is required.

The adapter takes one PostgreSQL transaction advisory lock shared across tables, pools and replicas before any positive KV SQL. It measures `pg_database_size(current_database())`, checks reserved headroom, and holds that lock through a fresh final measurement and COMMIT or ROLLBACK. The reserved amount is 64 MiB plus four times cumulative positive key+value input and replaced values plus 8 KiB per positive operation. Positive input is limited to 256 MiB and 1,048,576 operations per transaction. Each submitted positive operation counts at least one input byte, including an empty key/value, so a configured small input budget also bounds empty operations. Updates and changing conditional writes count too. Before each positive SQL, a metadata lookup counts the existing value's uncompressed length into the same bound and reservation, covering retirement-trigger journal copies. SQL failures, pressure refusal and late bound failures roll back the entire transaction; no commit acknowledgement is returned.

Optional overrides are `PGSL_PG_MAX_TRANSACTION_INPUT_BYTES` and `PGSL_PG_WRITE_RESERVE_BYTES`. All values are safe integer byte counts; malformed limits fail at startup. The reserve may be zero for isolated tests; production should retain the default. The exported refusal type is `PgWritePressureError`, with code `PGSL_WRITE_PRESSURE`.

Read-only and raw delete-only transactions do not take the admission lock or check the ceiling. A conditional compare-and-set with identical expected and new bytes uses a matching SELECT FOR UPDATE row proof, without creating a replacement tuple or retirement journal entry. It takes the database mutation lock before flushing any queued deletes in that proof call, but does not require growth admission; legacy resource deletion therefore remains available above the ceiling. The collector can therefore reclaim data above the ceiling. A mixed delete/write transaction is a writer, so its whole transaction is refused and rolled back if admission fails.

The ceiling measures physical database files, including heap, indexes and TOAST. WAL and other databases are outside this measurement: the gap between 48 GB and the 64 GB volume is deliberate operational headroom, not a promise about PostgreSQL WAL retention. The multiplier is conservative admission reserve rather than an exact physical/WAL accounting formula. Writers bypassing this adapter do not participate in its advisory lock.

Ordinary VACUUM may make pages reusable without reducing `pg_database_size`. The guard intentionally remains closed at its physical threshold until physical size is reduced or an operator reviews the ceiling. It does not grant speculative reuse credits or delete historical resources.

The bounded defaults preserve existing payload contracts: hosted package upload accepts 64 MiB of base64 (48 MiB compressed bytes), stored as approximately 64 MiB of opaque chunk values. The 256 MiB aggregate input allowance covers those values, metadata/indexes and replaced-value journal accounting; it is not an upload-size increase. Native resource representations remain capped at 8 MiB. The operation allowance covers the native 100,000-node model plus projected indexes and edges, including valid RDF bodies whose projections exceed 4096 writes. The same physical ceiling and precommit check remain binding; larger transactions must reserve proportionally more headroom.
