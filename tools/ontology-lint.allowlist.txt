# Known-drift allowlist for ontology-lint.
#
# ★ EMPTY, AND THAT IS THE POINT. It held 17 entries, and 13 of them were not drift at
# all — they were artifacts of this lint's own tokenizer, and the comments that pinned
# them said so out loud ("False positive from regex tokenization"). Two more were already
# dead: iep:evidenceForControl occurs only inside a `//` comment the scanner strips, and
# soc2:P4 occurs in no scanned .ts file at all. Fixing the tokenizer — see the two ★
# comments in ontology-lint.mjs — retired all fifteen, and the remaining ones became real
# declarations: iep:Causal + iep:Projection in docs/ns/iep.ttl, soc2:CC3.2 + soc2:CC4.2 in
# docs/ns/soc2.ttl (and in docs/ns/soc2.html, because a declared IRI whose HTML fragment
# does not resolve is the same 404 one level down).
#
# ★ THE LESSON THIS FILE COST: an allowlist keyed on a TRUNCATED token is many-to-one.
# `soc2:CC3` was pinned as a "regex false positive" for the declared soc2:CC3.1 — and that
# same pin silently covered soc2:CC3.2, emitted by packages/ops/src/index.ts and declared
# NOWHERE. Likewise soc2:CC4 over the undeclared soc2:CC4.2. Two SOC 2 control IRIs were
# masked by entries written to excuse a tokenizer bug. A gate that reports a coarser token
# than the one it checks cannot be allowlisted safely at all: the entry you write for the
# term you know about blankets every sibling you do not.
#
# Do not add an entry back. If code emits an owned-namespace term, either declare the term
# in docs/ns/<prefix>.ttl or change the emission. If the lint reports a term that no code
# emits, the TOKENIZER is wrong — fix it there, and say in a comment which real string
# misled it.
